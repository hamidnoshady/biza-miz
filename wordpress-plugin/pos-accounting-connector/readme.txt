اتصال امن و دوطرفهٔ فروشگاه ووکامرس به سامانهٔ فروش و حسابداری.

== Description ==

این افزونه فروشگاه ووکامرس شما را به سامانهٔ حسابداری متصل می‌کند:

* **از فروشگاه به حسابداری:** سفارش، برگشت وجه، محصول (ساده، متغیر، تنوع،
  گروهی، خارجی و هر نوع افزونهٔ دیگر)، مشتری، دسته‌بندی‌ها و ویژگی‌ها.
* **از حسابداری به فروشگاه:** موجودی انبار، قیمت، ویرایش محصول، تغییر وضعیت
  سفارش و ثبت برگشت وجه.

پنج رویداد زمان‌بندی‌شدهٔ جداگانه (ارسال/دریافت سریع، بازخوانی سفارش‌ها،
بازخوانی کاتالوگ، و بازخوانی روزانهٔ مشتریان و محتوا) هر کدام با دورهٔ خودشان
اجرا می‌شوند، و همهٔ کارها از خط فرمان هم در دسترس است: `wp pos-connector sync`.

همهٔ ارتباط‌ها از سمت وردپرس آغاز می‌شود؛ سامانهٔ حسابداری هیچ‌گاه به فروشگاه شما
وصل نمی‌شود. بنابراین فروشگاهی که پشت فایروال است یا آدرس ثابت ندارد هم بدون
تنظیم اضافه کار می‌کند.

= امنیت =

هر درخواست علاوه بر توکن، دارای مهر زمانی، شمارهٔ یک‌بارمصرف و امضای
HMAC-SHA256 روی متن دقیق درخواست است. توکن فقط برای همین اتصال معتبر است و
هر زمان می‌توانید آن را از پنل حسابداری تعویض کنید.

== Installation ==

1. پوشهٔ افزونه را در `wp-content/plugins/` قرار دهید و آن را فعال کنید.
2. در پنل اشوبه به «تنظیمات ← اتصال‌های فنی ← وردپرس و ووکامرس» بروید، یک
   اتصال از نوع «افزونهٔ وردپرس» بسازید و توکن نمایش‌داده‌شده را کپی کنید.
3. در پیشخوان وردپرس، منوی «اشوبه» را باز کنید؛ راهنمای راه‌اندازی در بخش
   «اتصال» نمایش داده می‌شود. آدرس سامانه و توکن را وارد کنید،
   «فعال‌سازی محلی افزونه» را بزنید و ذخیره کنید.
4. «آزمایش اتصال از وردپرس» را بزنید.
5. در بخش «همگام‌سازی» دورهٔ هر بازخوانی را انتخاب کنید. برای اجرای
   دقیق روی فروشگاه‌های کش‌شده یا کم‌بازدید، `DISABLE_WP_CRON` را در
   `wp-config.php` فعال کنید و یکی از این خطوط را در crontab سرور بگذارید
   (مسیر سایت را عوض کنید):

   `*/5 * * * * wp --path=/path/to/site pos-connector sync`

   یا برای اجرای همهٔ رویدادهای سررسید (بازخوانی سفارش، کاتالوگ، مشتری، محتوا):

   `*/5 * * * * wp --path=/path/to/site cron event run --due-now`

   خروجی `wp pos-connector status` همین راهنما را چاپ می‌کند.

== Frequently Asked Questions ==

= افزونه چگونه به‌روزرسانی می‌شود? =

افزونه در مخزن وردپرس نیست. منبع به‌روزرسانی یا گیت‌هاب همین پروژه است
(پیش‌فرض) یا سرور خودتان — که با تنظیم `POS_CONNECTOR_UPDATE_URL` در افزونه
انتخاب می‌شود. وردپرس خودش (دو بار در روز، روی چرخهٔ به‌روزرسانی‌های خودش)
بررسی می‌کند و نسخهٔ جدید را در «افزونه‌ها ← به‌روزرسانی‌های موجود» و «پیشخوان ←
به‌روزرسانی‌ها» نشان می‌دهد. نصب، همان به‌روزرسانی معمولی وردپرس است — با یک
کلیک، با به‌روزرسانی خودکار، یا با `wp plugin update pos-accounting-connector`.
بررسیِ دستی هم از صفحهٔ تنظیمات و با دستور `wp pos-connector check-update`
ممکن است.

بستهٔ نصبی هر نسخه با اکشن دستی «Build plugin zip» در گیت‌هاب ساخته می‌شود؛
خروجی آن (zip و در حالت سرورِ خودتان، update.json) را دانلود و روی هاست خودتان
قرار می‌دهید. راهنمای کامل: `docs/wordpress-plugin-updates.md`.

= همگام‌سازی هر چند وقت اجرا می‌شود? =

پنج رویداد زمان‌بندی‌شده دارد: همگام‌سازی سریع (هر ۵ دقیقه)، بازخوانی
سفارش‌ها، بازخوانی کاتالوگ، و بازخوانی روزانهٔ مشتریان و محتوا. با WP-Cron
پیش‌فرض وردپرس، این‌ها فقط هنگام بازدید از سایت اجرا می‌شوند. برای تولید،
`DISABLE_WP_CRON` را true کنید و crontab سیستمی با `wp pos-connector sync` یا
`wp cron event run --due-now` تنظیم کنید (جزئیات در بخش نصب و پیشخوان «اشوبه»).

= اگر سرور به‌روزرسانی (update.json) در دسترس نباشد? =

افزونه آخرین پاسخ موفق را نگه می‌دارد و خطا را فقط گاهی در گزارش رویدادها
ثبت می‌کند. برای بازگشت به GitHub، `POS_CONNECTOR_UPDATE_URL` را در
`pos-accounting-connector.php` خالی بگذارید یا فیلتر `pos_connector_update_url`
را override کنید. راهنما: `docs/wordpress-plugin-updates.md`.

= اگر سامانهٔ حسابداری در دسترس نباشد چه می‌شود? =

سفارش‌ها در صف افزونه می‌مانند و در اولین اجرای موفق ارسال می‌شوند. هیچ سفارشی
از دست نمی‌رود.

== Deploy notes (operators) ==

After upgrading to 1.6.4+ on an existing store:

1. Visit wp-admin once (or run `wp plugin activate pos-accounting-connector`) so
   the plugin can create `{prefix}pos_connector_queue` if it was missing.
2. Save a product in WooCommerce admin to confirm no white screen; check
   «اشوبه ← عیب‌یابی» if sync errors occur (they are logged, not fatal).
3. If `DISABLE_WP_CRON` is true, confirm system crontab runs
   `wp pos-connector sync` or `wp cron event run --due-now` every ~5 minutes
   (`wp pos-connector status` prints example lines).
4. Self-updates: if `updates.eshobe.app` is unreachable, the plugin stays on
   the last good version info; fix DNS/host or clear `POS_CONNECTOR_UPDATE_URL`
   to use GitHub until the manifest is back.

  تازه‌ثبت‌نام پس از اتصال دیده نمی‌شوند.
* **بازخوانی روزانهٔ مشتریان:** مشتریانی که از طریق واردکننده یا مسیرهای غیر
  استاندارد ساخته شده‌اند هم در صف قرار می‌گیرند (نقش customer و کاربران دارای
  سفارش).
* **صف ایمن‌تر:** رویداد ناموفق با عقب‌گرد نمایی از سر صف کنار می‌رود تا یک
  رخداد خراب، صدها رخداد سالم پشت سر خود را متوقف نکند.
* **مدیریت محتوای وردپرس:** مشاهده و ویرایش نوشته‌ها و برگه‌ها و همگام‌سازی
  رسانه‌ها از اپ «مدیریت وردپرس»؛ تغییرات محتوا به‌صورت خودکار ارسال می‌شود.
* درخواست «خروجی کامل محتوا» از سامانه پاسخ داده می‌شود.

= 1.1.0 =
* سه رویداد زمان‌بندی‌شدهٔ جداگانه: همگام‌سازی سریع (۵ دقیقه)، بازخوانی
  سفارش‌ها (۱۵ دقیقه) و بازخوانی کاتالوگ (ساعتی) — هر کدام با دورهٔ قابل تنظیم.
* ارسال درخت دسته‌بندی: دسته‌ها، برچسب‌ها، ویژگی‌ها و طبقه‌بندی‌های سفارشی.
* ارسال شناسهٔ تنوع (`variation_id`) کنار شناسهٔ محصول در هر قلم سفارش، تا
  سفارشی که از وب‌هوک می‌رسد و سفارشی که افزونه می‌فرستد دقیقاً به یک کالا
  متصل شوند.
* ارسال کل کاتالوگ، نه فقط محصولات ساده و متغیر: گروهی، خارجی و هر نوعی که
  افزونهٔ دیگری ثبت کرده باشد.
* کارهای تازه از سامانهٔ حسابداری: ویرایش محصول، تغییر وضعیت سفارش، ثبت برگشت
  وجه (بدون بازگرداندن وجه از درگاه).
* قلاب‌های تازه برای ذخیره و حذف تنوع‌ها.
* بازگشت نمایی برای رویدادهای ناموفق، تا یک ردیفِ خراب هر بار تلاش نکند.
* دستورهای WP-CLI: `status`، `sync`، `test` و `export`.

= 1.0.2 =
* نخستین انتشار عمومی.
* پشتیبانی کامل از محصولات متغیر (variable) و تنوع‌ها (variations): همگام‌سازی
  محصول متغیر اکنون تنوع‌های فرزند را نیز شامل می‌شود.
* ارسال فیلدهای کامل محصول (نوع، ویژگی‌ها، تنوع‌ها، گروه‌بندی، تصاویر) به
  سامانهٔ حسابداری.
* رفع مشکل عدم دریافت محصول در سامانه برای فروشگاه‌های خرده‌فروشی (retail).

= 1.0.1 =
* رفع خطای «invalid_json» در «آزمایش اتصال» و همگام‌سازی: درخواست‌های بدون محتوا
  اکنون به‌صورت یک شیء JSON خالی ارسال می‌شوند.

= 1.0.0 =
* نخستین انتشار: اتصال امضاشده، همگام‌سازی دوطرفه، صف ارسال، گزارش رویدادها و
  مدیریت اتصال.
