# Review an Excel product catalogue

Open **Settings → Data Transfer → Import** (`/settings/data-transfer`) and select **Product catalogue**, or use **Import from Excel** on the Products or Watch page (`/settings/data-transfer?import=catalogue`; legacy `/settings/transfer?import=catalogue` links redirect there). Both entry points open the same wizard inside the Import workflow. The import requires Data Transfer import access and inventory adjustment access for the active branch. Woo review also requires WooCommerce management access to the chosen store.

1. Upload the first worksheet of an XLSX file with headers on row 1. The limit is 2 MiB, 1,000 data rows and 100 columns. Confirm the SKU and name columns and map the remaining fields. Use a stable source name when importing future files from the same supplier. A previous review with the same headers can supply the mapping.
2. Assign product brands from the workbook or fallback:
   - If the file includes a mapped brand column, each populated row preserves its own brand independently.
   - If no brand column is mapped, enter a fallback brand name before previewing or applying; it is assigned to every row.
   - If a brand column is mapped with blank cells, the preview reports how many rows lack a brand and lets you enter an optional fallback brand for blank rows only, or leave them intentionally unbranded.
3. Review the row numbers, normalized values, effective brand provenance (workbook column vs operator fallback) and warnings. For each repeated SKU, choose the physical row that represents the item, or leave the group on hold. The source values and all duplicate row numbers are preserved.
4. Review local matches and approve creation or linking. Watch rows create one serialized model per SKU with typed watch specifications and no physical units. Retail families require a parent SKU, a consistent parent title, a named branch attribute axis and distinct option values on at least two sellable child SKUs. A file with ordinary model specifications produces simple products. Existing branch brands are matched case/script-insensitively and reused within the active branch only; new brands are created safely inside the branch without duplicating under concurrent imports.
5. Choose a Woo store and review the candidates and taxonomy IDs. A REST store is queried directly. On a current connector, request the read-only preview, then refresh after the connector polls. An older connector can expose its existing mirror with a clear verification warning. An ambiguous or incompatible match is held. Existing products are linked without replacing store presentation. Creating a draft requires explicit store confirmation, and creating missing categories or global attribute terms has its own opt-in. Variation drafts use the existing per-store attribute definition mappings.
6. Choose how the price, purchase/opening cost and quantity columns are used:
   - **Catalogue only** writes no price or stock (the original behaviour).
   - **Fill missing** (the recovery default) fills only a field of a matched existing product that the branch does not have yet: a null sale price, a null cost, a product with no stock row. An existing price, cost or stock is preserved. A product the file creates is still created without a price or stock, exactly as before.
   - **Update existing** replaces the selected values on the products the file identified. It never creates a product: an unknown SKU is held for review.
   Enter the workbook's money unit (Rial or Toman) explicitly. Every value is stored as integer Rial. A blank cell is never zero, a formula or error cell is never a value, an explicit zero in the sale-price column is held, and a purchase cost with stock on hand is held because receipts and lots own the carrying cost. Stock is applied as an absolute target through the reviewed stock-count service, which records the variance and refuses serial-, batch- and weight-tracked products; those rows stay held with the reason.
7. Confirm local application. Metadata, prices and stock have **separate** confirmations — the price/stock checkboxes appear only when the preview would write them. The wizard processes bounded batches and retains the reconciliation run and its audit history. Reopen the run to continue an interrupted apply. If the catalogue, a price or a stock level changed, use a fresh preview. Use the downloadable report to reconcile physical worksheet rows, including brand provenance, family members, per-field current/proposed values and held fields.
8. Confirm each selected store operation after the local item has applied. Refresh delivery status to see queued, processing, review, failed or Woo-confirmed outcomes. For families, the parent ACK creates the child jobs. Each child has its own status. A draft with no reviewed price remains a draft. This import creates metadata-only mappings with automatic price and stock pushes paused: a value applied locally is not pushed to the store from here.

The file workflow never creates a serial number, never invents a cost and never writes a stock balance directly. Prices go through `saveStockPrices` (immutable price history, cost guard) and quantities through `createItemStockCount` (reviewed delta, journal, tracking guard). Full Offline supports local review and apply. Hybrid uses the cloud-hosted settings workflow for Woo operations.
